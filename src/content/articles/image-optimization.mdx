Images are typically the largest single contributor to page weight, and the largest single lever for LCP. Done well, image delivery is invisible. Done badly, it is the performance bottleneck.

## Format priority

The format hierarchy in 2025 is straightforward:

1. **AVIF** for photographic content. Roughly 30 percent smaller than WebP at equivalent quality.
2. **WebP** as a fallback for browsers without AVIF (a shrinking set).
3. **JPEG** as a final fallback for legacy clients.
4. **SVG** for icons, logos, and any content that is geometric rather than photographic.
5. **PNG** only when transparency and lossless are both required.

Use the `<picture>` element to serve format negotiation:

```html
<picture>
  <source srcset="/img/hero.avif" type="image/avif" />
  <source srcset="/img/hero.webp" type="image/webp" />
  <img src="/img/hero.jpg" alt="..." width="1200" height="600" />
</picture>
```

## Sizing with srcset

A single image source is almost never optimal. The browser knows the device pixel ratio and viewport size; let it pick <Citation id="image-perf-mdn" />.

```html
<img
  src="/img/hero-800.jpg"
  srcset="/img/hero-400.jpg 400w, /img/hero-800.jpg 800w, /img/hero-1600.jpg 1600w"
  sizes="(max-width: 600px) 100vw, 800px"
  alt="..."
  width="1600"
  height="900" />
```

Two non-negotiables:

- Always declare `width` and `height`. They prevent CLS, even when CSS scales the image.
- Always set `sizes` if you use `srcset`. Without it, the browser assumes 100vw.

## Lazy loading

The native `loading` attribute is well-supported and beats every JavaScript polyfill on every metric <Citation id="html-spec-loading" />.

```html
<img loading="lazy" decoding="async" src="..." />
```

The exception: never lazy-load the LCP image. Doing so is the single most common mistake I see, and it costs roughly 500-1500ms of LCP time.

For the LCP image, opt in to high priority instead:

```html
<img fetchpriority="high" decoding="async" src="..." />
```

## When to preload

Preload is sharp. Use it only when:

- The image is the LCP element.
- It is loaded by CSS (e.g., `background-image`), where the browser cannot discover it from the HTML scan.
- You can name a single, definite URL.

```html
<link
  rel="preload"
  as="image"
  href="/img/hero-800.avif"
  type="image/avif"
  imagesrcset="/img/hero-400.avif 400w, /img/hero-800.avif 800w"
  imagesizes="(max-width: 600px) 100vw, 800px" />
```

## A practical checklist

- LCP image: `fetchpriority="high"`, no `loading="lazy"`, dimensions set.
- Below-the-fold images: `loading="lazy"`, `decoding="async"`.
- All images: AVIF + WebP + JPEG via `<picture>`, dimensions set, descriptive `alt`.
- CDN: encode all formats at multiple widths, serve via a single image-handling endpoint.

## Closing

Image work pays back faster than almost any other performance lever. A two-day audit of a content-heavy site will frequently lift LCP by a full second on the field 75th percentile.
